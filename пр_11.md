## 2. Короткий довідник агрегатних функцій

| Функція | Що робить | Поведінка з NULL |
|---|---|---|
| `COUNT(*)` | Рахує **усі рядки** групи | Включає рядки з NULL |
| `COUNT(col)` | Рахує рядки, де `col IS NOT NULL` | Ігнорує NULL |
| `COUNT(DISTINCT col)` | Рахує унікальні не-NULL значення | Ігнорує NULL |
| `SUM(col)` | Сума значень | Ігнорує NULL |
| `AVG(col)` | Середнє арифметичне | Ігнорує NULL (діли­ть на кількість не-NULL) |
| `MIN(col)` | Мінімум | Ігнорує NULL |
| `MAX(col)` | Максимум | Ігнорує NULL |

**Ключове правило:** усі агрегати крім `COUNT(*)` **пропускають NULL**. Це впливає на `AVG` найсильніше — якщо половина значень NULL, то `AVG` рахується тільки по половині.

## 3. Звіти з завдання — пояснення результатів

### 3.1. Кількість курсів у кожному підрозділі

```sql
SELECT
    d.code,
    d.name,
    COUNT(c.course_id) AS courses_count
FROM college.departments d
LEFT JOIN college.courses c ON c.department_id = d.department_id
GROUP BY d.department_id, d.code, d.name
ORDER BY courses_count DESC;
```

**Очікуваний результат:**

```
 code |        name              | courses_count
------+--------------------------+---------------
 IT   | Інформаційні технології  |             3
 FIZ  | Фізика                   |             1
 MAT  | Математика               |             1
```

**Пояснення словами:**

- `LEFT JOIN` потрібний, щоб відобразити й кафедри **без курсів** (COUNT для них дав би 0, а не NULL — така поведінка `COUNT(column)` корисна).
- `GROUP BY` збирає всі курси однієї кафедри в одну «купу», а `COUNT(c.course_id)` підраховує кількість у кожній купі.
- `ORDER BY` сортує звіт — від найбільшої кафедри до найменшої.

### 3.2. Середня кількість кредитів курсів

```sql
SELECT
    ROUND(AVG(credits), 2) AS avg_credits,
    SUM(credits)           AS total_credits,
    COUNT(*)               AS courses_total
FROM college.courses;
```

**Очікуваний результат:**

```
 avg_credits | total_credits | courses_total
-------------+---------------+---------------
        3.80 |            19 |             5
```

**Пояснення:** п'ять курсів із загальною кількістю 19 кредитів дають середнє 3.8. `ROUND(…, 2)` робить вивід читабельним — без нього PostgreSQL показав би `3.8000000000000000`.

### 3.3. Мінімум і максимум оцінок

```sql
SELECT MIN(grade), MAX(grade), AVG(grade), COUNT(grade), COUNT(*)
FROM college.enrollments;
```

**Очікуваний результат:**

```
 min | max |  avg  | graded_count | total_enrollments
-----+-----+-------+--------------+-------------------
 65  | 92.5| 81.75 |            5 |                 6
```

**Пояснення:**

- Один запис має `grade = NULL` (Іваненко на DB) — його `MIN/MAX/AVG` **не враховують**, але він потрапляє в `COUNT(*)`.
- `COUNT(grade) = 5` (5 ненульових оцінок), `COUNT(*) = 6` (усі реєстрації).
- Якби всі оцінки були NULL, `MIN/MAX/AVG` повернули б **NULL**, а `COUNT(grade) = 0`.

### 3.4. Курси з ≥ 2 реєстраціями (HAVING)

```sql
SELECT course_id, COUNT(*) AS enrollments
FROM college.enrollments
GROUP BY course_id
HAVING COUNT(*) >= 2
ORDER BY enrollments DESC;
```

**Очікуваний результат (на поточних даних):**

```
 course_id | enrollments
-----------+-------------
         1 |           2    -- Бази даних
```

На наших даних лише курс `DB` має 2 студентів. Усі інші курси (WEB, ALG, PH1, MA1) мають по одному студенту й не проходять у звіт.

**Якби не було `HAVING`**, у результаті з'явилися б всі курси, включно з тими, хто має 1 реєстрацію.

## 4. WHERE vs HAVING — демонстрація різниці

Це одне з найважливіших місць SQL, тому розглядаємо детально.

### 4.1. Порядок виконання SQL-запиту

```
1. FROM / JOIN  ──▶  збираємо рядки з таблиць
2. WHERE        ──▶  фільтруємо ОКРЕМІ РЯДКИ
3. GROUP BY     ──▶  групуємо рядки
4. HAVING       ──▶  фільтруємо ГРУПИ
5. SELECT       ──▶  вибираємо колонки / агрегати
6. ORDER BY     ──▶  сортуємо
7. LIMIT        ──▶  обрізаємо
```

`WHERE` працює **до** групування (на рівні рядків), `HAVING` — **після** (на рівні груп).

### 4.2. Приклад з WHERE

```sql
SELECT course_id, COUNT(*) AS enrollments_with_good_grade
FROM college.enrollments
WHERE grade >= 80           -- спочатку відкидаємо рядки з оцінкою < 80
GROUP BY course_id;
```

**Крок за кроком:**

1. Беремо **всі** 6 рядків `enrollments`.
2. WHERE лишає тільки ті, де `grade >= 80` → 3 рядки (оцінки 92.5, 90.0, 88.0).
3. Групуємо по `course_id`.
4. Рахуємо кількість у кожній групі.

**Результат — кількість *високих* оцінок на курс.**

### 4.3. Приклад з HAVING

```sql
SELECT course_id, COUNT(*) AS total_enrollments
FROM college.enrollments
GROUP BY course_id
HAVING COUNT(*) >= 2;       -- потім лишаємо тільки групи з розміром >= 2
```

**Крок за кроком:**

1. Беремо **всі** 6 рядків.
2. Групуємо по `course_id`.
3. Рахуємо `COUNT(*)` для кожної групи.
4. HAVING лишає тільки групи, де лічильник ≥ 2.

**Результат — курси з популярністю ≥ 2 реєстрації.**

### 4.4. Чому WHERE не можна з агрегатом

```sql
-- ПОМИЛКА:
SELECT course_id, COUNT(*)
FROM college.enrollments
WHERE COUNT(*) >= 2         -- ❌ не можна!
GROUP BY course_id;
```

```
ERROR: aggregate functions are not allowed in WHERE
```

**Причина:** на момент `WHERE` **групування ще не відбулося** — агрегат `COUNT(*)` обчислюється лише на кроці 4 (після GROUP BY). WHERE бачить окремі рядки, а не групи.

### 4.5. Разом WHERE + HAVING

Типовий звіт:

```sql
SELECT course_id, COUNT(*), AVG(grade)
FROM college.enrollments
WHERE grade IS NOT NULL      -- WHERE: відсіяти NULL-рядки
GROUP BY course_id
HAVING COUNT(*) >= 2         -- HAVING: лише групи з 2+ записами
ORDER BY AVG(grade) DESC;
```

`WHERE` прибирає NULL на вході, щоб `AVG` рахувалося чисто. `HAVING` потім обирає великі групи.

## 5. Операції над множинами

### 5.1. Чотири базові операції

| Операція | Семантика | Дублікати у результаті |
|---|---|---|
| `UNION` | Усі рядки з A + усі з B | **Прибирає** |
| `UNION ALL` | Усі рядки з A + усі з B | Зберігає |
| `INTERSECT` | Тільки ті, що є **одночасно** в A і B | Прибирає |
| `EXCEPT` | Рядки з A, яких немає в B | Прибирає |

### 5.2. UNION vs UNION ALL — головна різниця

На штучних даних:

```sql
WITH set_a AS (SELECT * FROM (VALUES ('DB'), ('WEB'), ('ALG')) t(code)),
     set_b AS (SELECT * FROM (VALUES ('DB'), ('ALG'), ('ML'))  t(code))
SELECT code FROM set_a UNION     SELECT code FROM set_b;   -- 4 рядки
SELECT code FROM set_a UNION ALL SELECT code FROM set_b;   -- 6 рядків
```

| Запит | Результат | Потужність |
|---|---|---|
| `UNION` | `ALG, DB, ML, WEB` | **4** (DB і ALG не дублюються) |
| `UNION ALL` | `DB, WEB, ALG, DB, ALG, ML` | **6** (усі рядки обох множин) |

**Коли що використовувати:**

- **UNION** — коли потрібен унікальний список. Платимо продуктивністю: PostgreSQL робить додатковий етап сортування + видалення дублікатів.
- **UNION ALL** — коли дублікати не заважають або точно відсутні. **Швидше**, бо не треба сортування.

**Правило:** якщо точно знаєте, що дублікатів не буде (наприклад, об'єднуєте непересічні категорії), пишіть `UNION ALL` — оптимізатор подякує.

### 5.3. INTERSECT та EXCEPT

```sql
-- INTERSECT: тільки спільні
SELECT code FROM set_a INTERSECT SELECT code FROM set_b;
-- Результат: ALG, DB (потужність 2)

-- EXCEPT: A мінус B
SELECT code FROM set_a EXCEPT SELECT code FROM set_b;
-- Результат: WEB (потужність 1)

-- EXCEPT не симетричний:
SELECT code FROM set_b EXCEPT SELECT code FROM set_a;
-- Результат: ML (потужність 1)
```

### 5.4. Потужності результатів

На наших штучних даних:

| Операція | Результат | Потужність |
|---|---|---|
| `set_a` | `{DB, WEB, ALG}` | 3 |
| `set_b` | `{DB, ALG, ML}` | 3 |
| `set_a ∪ set_b` (UNION) | `{DB, WEB, ALG, ML}` | 4 |
| `set_a ∪ set_b` (UNION ALL) | `{DB, WEB, ALG, DB, ALG, ML}` | 6 |
| `set_a ∩ set_b` (INTERSECT) | `{DB, ALG}` | 2 |
| `set_a − set_b` (EXCEPT) | `{WEB}` | 1 |
| `set_b − set_a` (EXCEPT) | `{ML}` | 1 |

Формально для будь-яких A і B: `|A ∪ B| = |A| + |B| − |A ∩ B|`. У нас: 3 + 3 − 2 = 4. ✓

### 5.5. Практичний приклад

Хто записаний на курс DB, але **не** на WEB?

```sql
SELECT student_id FROM enrollments e JOIN courses c USING (course_id) WHERE c.code = 'DB'
EXCEPT
SELECT student_id FROM enrollments e JOIN courses c USING (course_id) WHERE c.code = 'WEB';
```

Повертає тих студентів, які **тільки на DB**, без WEB.

### 5.6. Вимоги до операндів

- **Однакова кількість колонок** в обох SELECT.
- **Сумісні типи даних** попарно.
- **Імена колонок беруться з першого** SELECT.

```sql
-- Не спрацює — різна кількість колонок
SELECT code, title FROM courses
UNION
SELECT student_id FROM students;
-- ERROR: each UNION query must have the same number of columns
```

## 6. Прикладний звіт — «Топ курсів за кількістю студентів»

```sql
SELECT
    c.code                     AS course_code,
    c.title                    AS course_title,
    d.code                     AS dep_code,
    COUNT(e.student_id)        AS student_count,
    ROUND(AVG(e.grade), 2)     AS avg_grade,
    MIN(e.grade)               AS min_grade,
    MAX(e.grade)               AS max_grade
FROM college.courses c
LEFT JOIN college.enrollments e ON e.course_id = c.course_id
JOIN college.departments d      ON d.department_id = c.department_id
GROUP BY c.course_id, c.code, c.title, d.code
HAVING COUNT(e.student_id) > 0
ORDER BY student_count DESC, avg_grade DESC NULLS LAST
LIMIT 10;
```

**Очікуваний результат (на поточних даних):**

```
 course_code | course_title           | dep_code | student_count | avg_grade | min_grade | max_grade
-------------+------------------------+----------+---------------+-----------+-----------+-----------
 DB          | Бази даних             | IT       |             2 |     92.50 |     92.50 |     92.50
 WEB         | Вебтехнології          | IT       |             1 |     85.00 |     85.00 |     85.00
 ALG         | Алгоритми              | IT       |             1 |     78.00 |     78.00 |     78.00
 PH1         | Загальна фізика        | FIZ      |             1 |     65.00 |     65.00 |     65.00
 MA1         | Дискретна математика   | MAT      |             1 |     88.00 |     88.00 |     88.00
```

**Пояснення:**

- `LEFT JOIN` — щоб курси без студентів теж з'явилися (їх `HAVING` відсіє).
- `HAVING COUNT(e.student_id) > 0` — фільтр на груповому рівні.
- Подвійне сортування — спочатку за популярністю, потім за якістю.
- `NULLS LAST` — курси без оцінок потрапляють у кінець, а не на початок.
- `LIMIT 10` — захист від «дурноти» звіту, якщо курсів тисячі.

## 7. Відповіді на питання для захисту

### 7.1. Чому WHERE не можна використати для фільтрації після групування?

Через **порядок виконання** SQL-запиту:

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

На момент `WHERE` **групування ще не сталося**. SQL-двигун обробляє окремі рядки, а не групи. Агрегати (`COUNT`, `SUM`, `AVG`...) обчислюються **тільки після GROUP BY** — на етапі 3. Тому вжити агрегат у WHERE фізично неможливо:

```sql
-- ПОМИЛКА:
SELECT course_id FROM enrollments
WHERE COUNT(*) >= 2        -- ❌
GROUP BY course_id;
```

```
ERROR: aggregate functions are not allowed in WHERE
```

Для фільтрації **після** агрегації існує `HAVING`:

```sql
SELECT course_id FROM enrollments
GROUP BY course_id
HAVING COUNT(*) >= 2;      -- ✅
```

**Коротке правило:**

- **WHERE** — фільтр **рядків** (до групування), не може містити агрегатів.
- **HAVING** — фільтр **груп** (після агрегування), не може містити «негрупованих» колонок, крім тих, що в GROUP BY.

### 7.2. Що повертає COUNT(*) за відсутності рядків?

`COUNT(*)` завжди повертає число — **0**, а не NULL.

```sql
SELECT COUNT(*) FROM enrollments WHERE 1 = 0;
-- Результат: 0
```

Це важлива особливість `COUNT`, відмінна від інших агрегатів:

```sql
SELECT COUNT(grade), SUM(grade), AVG(grade), MIN(grade), MAX(grade)
FROM enrollments WHERE 1 = 0;
--  count | sum  | avg  |  min |  max
--      0 | NULL | NULL | NULL | NULL
```

**Чому так:** `COUNT` за визначенням рахує, а «порахувати нуль» — цілком коректна операція. А ось обчислити суму чи середнє з порожнього набору не має сенсу — тому NULL.

**Практичний наслідок:**

```sql
SELECT 'Нема оцінок у БД' WHERE (SELECT AVG(grade) FROM enrollments) IS NULL;
-- спрацює, якщо enrollments порожня або всі grade = NULL
```

### 7.3. У чому різниця між UNION і UNION ALL?

| Критерій | `UNION` | `UNION ALL` |
|---|---|---|
| Дублікати | **Видаляє** | Залишає |
| Швидкість | Повільніший (потрібне сортування + дедуплікація) | **Швидший** (просто з'єднання) |
| Семантика | «Унікальні елементи обох множин» | «Усе з обох множин, по порядку» |

**Ілюстрація:**

```
set_a = {1, 2, 3}
set_b = {2, 3, 4}

UNION:     {1, 2, 3, 4}             -- 4 унікальні
UNION ALL: {1, 2, 3, 2, 3, 4}       -- 6 рядків зі збереженням дублікатів
```

**Коли що:**

- `UNION ALL` — коли дублікатів немає або вони не заважають. Завжди швидше.
- `UNION` — коли треба унікальний результат. Платимо продуктивністю.

**Оптимізація:** якщо ви об'єднуєте дані з непересічних множин (наприклад, замовлення за січень і за лютий), пишіть `UNION ALL` — дублікатів точно не буде, а `UNION` даремно робитиме сортування.

### 7.4. Як NULL впливає на агрегатні функції?

**Усі агрегати крім `COUNT(*)` ігнорують NULL.**

Це важливо розуміти, щоб не отримати несподіваних результатів.

**Приклад — AVG:**

```sql
-- enrollments: grades = {92.5, 85, NULL, 78, 65, 88}
SELECT AVG(grade) FROM enrollments;
-- 81.7 (= (92.5+85+78+65+88) / 5), ділиться на 5, а не на 6!
```

**Приклад — COUNT:**

```sql
SELECT
    COUNT(*)     AS all_rows,     -- 6 (включає NULL)
    COUNT(grade) AS non_null,     -- 5 (тільки не-NULL)
    COUNT(1)     AS also_all;     -- 6 (= COUNT(*))
```

**Приклад — SUM:**

```sql
SELECT SUM(grade) FROM enrollments;
-- 408.5 (= 92.5+85+78+65+88, NULL не додається)

-- Якщо ВСІ значення NULL — повертає NULL, не 0:
SELECT SUM(grade) FROM enrollments WHERE grade IS NULL;
-- NULL
```

**Приклад — MIN / MAX:**

Ігнорують NULL. Якщо всі NULL — повертають NULL.

**Приклад — DISTINCT:**

```sql
SELECT COUNT(DISTINCT grade) FROM enrollments;
-- 5 унікальних не-NULL оцінок; NULL не входить
```

**Практичні наслідки:**

1. **Перевіряйте COUNT(*) vs COUNT(column)** — якщо різні, у колонці є NULL.
2. **AVG не дає того, що очікувалося** — ділиться на `COUNT(column)`, не на `COUNT(*)`.
3. **Якщо треба трактувати NULL як 0 в AVG** — використовуйте `COALESCE`:
   ```sql
   SELECT AVG(COALESCE(grade, 0)) FROM enrollments;
   -- 68.08 (= (92.5+85+0+78+65+88) / 6)
   ```
4. **SUM на порожньому наборі = NULL**. Якщо потрібно 0:
   ```sql
   SELECT COALESCE(SUM(grade), 0) FROM enrollments WHERE 1 = 0;
   -- 0
   ```

## Висновок

У межах роботи складено й виконано повний набір агрегатних звітів на схемі `college.*`:

- **Базові агрегати** — `COUNT`, `AVG`, `MIN`, `MAX`, `SUM` з групуванням по кафедрах і курсах.
- **HAVING** — фільтрація груп після агрегації.
- **Порівняння WHERE vs HAVING** — показано порядок виконання SQL і коли який використовувати.
- **Операції над множинами** — `UNION`, `UNION ALL`, `INTERSECT`, `EXCEPT` з обчисленням потужностей результатів.
- **Прикладний звіт «Топ курсів»** — з групуванням, агрегацією, фільтрацією та сортуванням.
- **Поведінка NULL** в агрегатах — ключова деталь, яка впливає на правильність розрахунків.

Агрегація і групування — основа аналітичних запитів у SQL. Разом з `JOIN`, підзапитами й віконними функціями (CTE, window functions) вони закривають переважну більшість задач звітності. Наступним кроком стануть складні JOIN і віконні функції для рейтингів, часових серій і аналітики по групах.
